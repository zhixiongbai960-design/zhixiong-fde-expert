# FDE 实战专家技能

把客户的原话、一个模糊想法，或一份还拿不准的方案交给它。它会帮你分清真实需求、找出关键缺口，把下一步整理成能讨论、能交接、能核验的具体成果。

**适用范围声明：参照《志雄 FDE 实战指南》的项目分层，本套解决方案主要适用于 20 万元以下的 FDE 项目。**

指南中的金额是能力与风险的经验参照，不是硬门槛或统一报价。更大项目也可以参考其中的方法，再根据实际复杂度与风险补充方案。分层依据见[第 01 篇“我的六档判断”](references/guide__fde_01.md#3我的六档判断)。

## 怎么用

把下面这句话和仓库链接发给支持 Skill 的 Agent：

> 请帮我安装「FDE 实战专家技能」：https://github.com/zhixiongbai960-design/zhixiong-fde-expert

装好后，直接告诉它你遇到的问题。比如：

> 用 FDE 实战专家技能帮我看看这段客户聊天：客户说“想做一个自动周报工具”，但还没说清楚谁用、数据从哪来。请帮我区分已经明确的需求和需要继续问的问题。

不需要先读完资料，也不用从头走一遍固定流程。你卡在哪一步，就从哪一步开始；如果手头已经有聊天记录、需求文档、方案或测试结果，直接提供获准使用的材料即可。

仓库根目录就是完整技能包，入口是 [SKILL.md](SKILL.md)。Agent 需要支持技能安装，并能读取包内文件；具体安装方式由它所在的平台决定。安装后可以让它报告版本 `0.6.0`，并实际读取一份包内方法和正文，确认资料完整。已有旧版时先备份到技能目录之外，不直接覆盖或混装。这里不承诺所有平台都能一键安装。


## 0.6.0 怎么工作

先识别你正在哪个环节、已经做到哪一步、本轮想拿到什么结果，再按经验给判断。常见且信息充分的问题直接回答；有推测时说清依据和缺口，只追问会改变判断的信息。需要完整设计或深入解释时，才打开对应方法和蓝本知识点，不再每次先读几篇原文。

需求分析按已有成果逐级推进：找到需求 → 找到真需求 → 找到可落地的场景和环节 → 增量提示风险、问题和潜在需求。已经分析过的内容不从头问一遍，潜在需求也不会自动加进当前MVP。

课堂设计使用三层组合：
1. AI Agent + Skill。
2. AI Agent + Skill + API + 数据库，数据库也可以是多维表格。
3. 在第二层基础上增加 Web 应用。

按任务选足够的组合，不默认越复杂越好。MVP与业务Skill主要给场景选择和IPO（输入、处理、输出）；验证、部署与交付给方法和路线，具体实现仍交其他合适工具。

项目完成后，标准流程沉淀为SOP或Skill方法，判断经验进入决策库，情绪与个人体验进入日常觉察，和开篇的知识库形成闭环。已有知识库建设和需求分析能力继续复用。

## 下载与独立使用

- [完整专家技能ZIP](https://github.com/zhixiongbai960-design/zhixiong-fde-expert/raw/refs/heads/main/packages/zhixiong-fde-expert-0.6.0.zip)：只装这一个即可使用内置全部方法。
- [21个独立技能分包合集](https://github.com/zhixiongbai960-design/zhixiong-fde-expert/raw/refs/heads/main/packages/zhxbai-fde-independent-skills-0.6.0.zip)：先解开合集，再选其中一个技能ZIP安装；不要把合集作为单个Skill上传。
- [模块与依赖清单](references/registry.json)：保留原18模块名称，新增能力诊断、电梯演讲、复盘沉淀。

每个可安装包内最多只有一层子目录；独立包携带自身方法、相关依赖和知识资料，不要求先安装总专家。不需要同时安装全部21个小技能。

新增工具分别是：
- **zhxbai-fde-diagnose**：基于目标任务、实际作品与操作证据，分析学习缺口并给下一项练习，不作职业认证或凭问卷给精确分数。
- **zhxbai-fde-pitch**：围绕同一事实底稿，按客户、伙伴、投资人或内部负责人调整电梯演讲重点。
- **zhxbai-fde-reflect**：把过程中的流程、判断和情绪分别整理为可沉淀条目，不自动写入私人知识库。

## 接触客户：他说了很多，真正要解决什么？

### 客户的原话很散，不知道哪些算需求

它可以沿着聊天记录找出具体场景、当前做法和不满意的地方，区分客户明确说过的话、可能的解释和还缺的证据。你得到的是有原话依据的判断和下一次该问的问题，而不是替客户猜想法。

你可以问：“帮我看看这段聊天，客户到底想改善哪一步？哪些已经说清楚，哪些只是我们自己的猜测？”

### 有合作意向，但不知道值不值得继续跟

它可以帮你检查实际使用者、决策者、配合条件、数据来源与投入边界，判断当前更适合继续了解、缩小切口，还是先等一个关键条件。老板说“可以试试”，不会自动被当成预算、数据和上线权限都已到位。

## 梳理需求：有想法，怎样变成一个能做的小项目？

### 客户只说“用 AI 提效”，需求还很模糊

它会围绕当前最影响判断的问题继续追问，把场景、问题、目标和现有流程逐步问清楚。需要访谈时，每轮聚焦一个核心问题；已有足够材料时，直接整理，不让你把说过的内容再讲一遍。

你可以问：“这是我们现在做周报的过程。帮我找最值得先解决的一处问题，不急着设计整个系统。”

### 想做的功能太多，不知道第一版留什么

它可以帮你切出最小可用版本（MVP），写清输入、输出、业务规则、异常情况和验收标准。还没确定的内容会留作假设或待确认项，让你看清哪些可以先推进，哪些会影响开工。

## 设计方案：需求确定了，方案怎么落到细节？

### 不知道流程、数据和工具该怎么配合

它可以把确认的需求整理成产品流程、组件职责、数据字段、接口约定、权限和异常处理，帮助你判断哪些适合交给 AI，哪些必须由确定性的程序或规则完成。

你可以问：“这个需求第一版该怎样设计？请把用户怎么操作、数据怎么流转、失败时怎么办讲清楚，整理成开发者能接手的说明。”

### 已经有设计文档，担心交给开发后反复返工

它可以对照需求评审文档，指出具体位置的矛盾、遗漏和未确认条件，给出修改建议与核验办法。需要时也能只读查看你授权提供的现有代码、日志和测试记录，检查实现证据是否支持设计判断。

## 验证想法：演示能跑，怎样知道真的有用？

### 客户想先看效果，但成功标准还没说清

它可以帮你设计小范围验证（POC），明确验证什么、用什么样本、谁来判断、哪些失败要保留，以及结果如何影响下一步。没有依据时，不先承诺准确率、收益或工期。

你可以问：“我们想验证订单分类是否值得继续做。请帮我设计验证方案，先明确标准和样本，不要预设效果数字。”

### 演示不错，客户想直接转正式项目

它可以帮你分清“演示成功”和“真实业务可用”之间还缺什么，检查实际数据、权限、稳定性、人工接管和验收约定，整理转正式项目前需要补齐的证据。

## 推进项目：人、范围和承诺卡住了怎么办？

### 老板同意了，实际使用的人却不配合

它可以梳理谁负责、谁使用、谁有权提供数据和批准操作，帮助你准备沟通内容与配合清单。遇到多个卡点时，优先找会改变方案、容易错过或需要等待的关键条件，不把“继续写代码”当成唯一进展。

### 客户临时加需求，报价和工期都开始失控

它可以对照已确认范围，整理变更带来的工作、费用、时间和责任影响，帮助你准备报价说明、变更讨论和付款安排。最终价格、合同承诺与是否继续合作，由你和有权负责人决定。

## 验收交付：做完了，怎样让客户接得住？

### 功能看起来都齐了，不知道是否可以交付

它可以把需求和验收证据一项项对应，设计测试场景、异常检查和手工核验步骤，区分已经验证、只做了演示、尚未确认的部分。文档写了“通过”，不等于真实环境已经跑通。

你可以问：“这是需求清单和测试结果。帮我找还缺的交付证据，以及上线前谁需要确认什么。”

### 担心交出去之后没人会用、出了问题没人管

它可以帮你整理操作说明、接管责任、故障处理、维护范围和未完成事项，让接手的人知道平时怎么用、异常找谁、什么时候需要暂停或回退。

## 运行复盘：项目结束后，怎样把经验留下来？

### 上线后出现问题，不知道先查什么

它可以根据你提供的现象、日志和变更记录，帮助区分事实与猜测，提出排查顺序和需要补充的证据。实际停服、改权限或修改生产系统，仍由有权执行者处理。

### 想复用这次经验，或者拿来做教学案例

它可以帮助整理可复用的方法、适用条件和失败教训，也能把获准材料改写成教学练习。新项目只复用方法，不会把旧项目的客户资料、授权和验收条件直接搬过来。

## 把它当作项目参谋

它负责分析、设计、评审、工程交接与推进建议。业务代码、应用、接口、可运行测试脚本和业务 Skill 的实现，需要交给你另选的开发者或专门工具；它也不会通过委派接管实现。你仍然可以得到具体的规格、接口示例、测试策略和验收标准，而不只是一句“做不了”。

它不替你作最终决定，也不能保证项目成功、客户认可或法律效力。涉及法律、财税或行业安全的正式结论，请交相应专业人员核验。技能的调用本身不代表获得发消息、签约、付款、发布或操作系统的授权。

提供材料前，请确认你有权使用。包内资料可以本地读取，但所用 Agent 如果连接云端模型，处理的内容可能传给模型服务；只限本机的数据需要先确认整条处理链路，不确定时用获准脱敏或合成材料。

作者：**白志雄**。**志亚科技出品**。

本技能结合[《志雄 FDE 实战指南》](https://github.com/zhixiongbai960-design/zhixiong-fde-guide)的场景经验与《FDE 全流程知识与方法蓝本》的知识释义，内置 33 篇完整指南文字、234 个蓝本知识点、21 个方法模块和 MVP 规格模板。指南适合按篇学习，技能则帮助你把方法用在眼前的问题上。资料按需读取，不需要另外安装一组小技能；图片是可选在线资源，不影响本地文字方法的使用。

当前版本为 **0.6.0**。总专家与独立模块由同一份方法源生成，安装包是固定快照，不会随仓库更新自动升级。来源与打包记录见 [PROVENANCE.json](PROVENANCE.json) 和 [RELEASE.json](RELEASE.json)。本版验证范围见[验证说明](references/qa__validation-0.6.0.md)：包装与文件检查、合成案例回答模拟、已发现问题的修复回归分别记录，不代表所有平台自动发现、真实业务验收或实际响应速度已经验证。
