# 项目电梯演讲

帮助用户把真实项目向当前听众讲清楚。交付可直接讲的短稿及必要的缺口，不先推荐文章。已有项目资料就直接利用；只问最影响表达的一项缺口，通常是听众及本次希望对方采取的行动。不因换听众重做需求分析。

## 共用事实，不同重点

先提取产品名称、类型、目标用户、痛点或需求、差异化价值、核心功能，以及实际验证状态。名称未定可用明确的暂名，不编客户数、营收、收益、准确率或背书。把已实现、已验证、计划和假设分开。

- 面向客户：先说他正在承受的问题、具体使用场景、已有结果、采用条件和下一步；不把方案讲成技术清单。
- 面向合作伙伴或共创者：突出适用客户、双方分工、互补价值、交接条件与待讨论事项；不擅自许诺收入分成或资源。
- 面向投资人：突出目标市场的具体问题、产品差异、已有验证及商业假设、当前需要；无数据时不编规模或财务预测。
- 面向讲师、同学或评审：突出需求到方案的取舍、本人完成部分、演示证据、限制和下一轮验证。
- 面向内部负责人：突出业务价值、投入、风险、责任及需其决定的事项；不把请求批准写成已批准。

## 可直接使用的产物

按实际时长写口语稿，未指定时先给约一分钟版本，必要时另给一句话版本。自然串起「为谁解决什么问题 → 怎么解决及为何这样选 → 现在证明到哪 → 希望听众下一步做什么」，不机械塞满所有栏目。用户要的是方法时，给结构和当前项目的一段示范；要路演稿时交完整稿。

同项目不同版本须共用事实底稿，变化的是排序和强调。未知的关键数字省略或明确待补，不能在润色时变成承诺。快速检查：陌生听众是否知道是什么、给谁用、为什么值得用；核心功能是否对应需求；差异是否有依据；演示和未来计划是否区分；结尾行动是否匹配当前授权与项目成熟度。指出一项最值得改的表达，避免堆满评审术语。

本方法来自用户 2026-11-12 对课堂电梯演讲的确认；它是应用层指导，不冒充指南逐字原文。只提供稿件与建议，不自动发送、发布或代为作出商业承诺。
