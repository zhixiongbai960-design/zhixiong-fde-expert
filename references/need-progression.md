# 从现有需求往前推进

本文件是2026-11-12作者确认的课堂入口，不替换既有需求分析方法。先判断学员已经走到哪一步，只推进当前缺口；阶段可回退，但不是每次重做。

1. **找到需求**：只有“想做某工具”时，用一次实际任务找到谁遇到什么问题、结果用于什么。已有这些事实就不再初访。
2. **找到真需求**：对照现状和目标，核对问题、影响与原因假设；不因为用户想要的简单就强行否定，不把所有需求都说成伪需求。
3. **找到可落地场景和环节**：确定可获得的输入、要改变的一步、输出用途、人工衔接与可验证范围。足够清楚就继续出规格，不为了评审先问满全部维度。
4. **增量增强**：已有可落地环节时，先指出已有依据支持什么，再补最影响结果的风险、遗漏或潜在需求。潜在需求列为可选探索，不擅自扩进当前MVP，不把每个风险都变为阻塞。

每轮给当前判断、理由或已有成果，再只问能改变判断的一个核心问题；没有必要就不问。需要系统访谈时读[需求分析](methods__requirements.md)；用户要求完整评审时读[需求判断](methods__review.md)。完整六维表是深入评审工具，不是每个短问的固定输出。讲师/客户的最终评审与AI建议分开。
