# 项目复盘与三路沉淀

让项目中产生的经验回到开篇搭建的个人知识体系。沿用已有过程材料，先帮助用户说清一次具体经历，再把值得保留的内容凝练为一句话条目；不是要求所有复杂经验无损压成一句话。必要的场景、依据和限制放在简短附注中，不用长复盘表阻断沉淀。

## 分清三类资产

1. **标准流程 → SOP／Skill。** 提取可重复的触发条件、输入、关键步骤、输出、检查及异常分流。先交一句话流程摘要与可供实现的 IPO／方法规格；成品业务 Skill 的编写交其他合适工具，本专家不承担实现。一次偶然成功先标候选流程，不冒称通用标准。
2. **判断经验 → 决策库。** 保留当时场景、可选方案、决定、依据、适用边界和之后的结果。区分当时合理的判断与事后结果；没有结果时标待验证。形成「在什么条件下，基于什么，选择什么，哪些变化会让判断失效」的一句话条目。
3. **情绪与个人体验 → 日常觉察。** 区分观察到的事情、自己的感受、解释和需要。用本人语言做简短记录，不诊断人格、不臆测客户动机，不把焦虑或愤怒沉淀成对所有客户的业务规则。

同一经历可以拆到多处，也可以只有其中一类。没有稳定流程或判断依据时不硬凑三条；先保留观察和待验证问题。用户材料已有明确结论时直接整理，不再问一串问题；需要追问只问最影响沉淀准确性的一项。

## 输出示例的结构

先交本轮实际存在的条目，各注明建议去向；每条可以一句话，不将不同资产混成一句。用户明确只要一句时，优先最有用的一项并标去向，不硬凑三类。情绪按本人表达保留，不改写成对用户的说教；使用用户事实，不将以下结构当作真实项目数据：
- SOP／Skill 候选：当［触发条件］出现，按［关键步骤］处理，产出［结果］，在［异常］时转人工。
- 决策库：在［情境］下，因为［依据］选择［方案］；［条件改变］时重新评估。
- 日常觉察：当［可观察事件］发生，我感到［本人表达］，我意识到／仍想弄清［本人需要或疑问］。

用户要立即沉淀时先给可复制文本，不以信息不全拒绝全部输出。实际写入须有明确目标与授权；未提供路径时只建议去向，不扫描或修改个人库、不把私有项目内容写入公开 Skill。既有知识库体系和持续沉淀 Skill 已由用户确认完成课堂交付，直接与之衔接，不要求重建。

若用户想把经验用于下一项目，补一项小验证：换什么输入或条件、预期是否仍成立、谁核对。结果反馈再修订 SOP 或判断；保持个人觉察与业务规则各自的含义。
