# 课堂成果与工具闭环

作者2026-11-12确认：现场讲方法，学员带走可持续使用的工具。专家负责判断、方法、设计和交接，具体实现由其他合适工具完成，不把缺少实现工具当成这套参谋的交付缺口。

| 环节 | 学员可拿走的成果 | 模块与现状 |
|---|---|---|
| 找自己、搭知识库 | 初级知识结构、持续沉淀方法与已有Skill；课堂讲记什么、怎么记、为什么记 | 现有知识库体系已完成第一期交付；本包knowledge仅负责项目材料整理，不替换或重做原体系 |
| FD能力诊断 | 基于当前任务的五维证据画像、缺口和下一项练习 | 新增diagnose；不是职业认证或自评分数 |
| 需求分析与增量评审 | 从需求、真需求到可落地环节，再补风险/潜在需求；需求规格 | 复用已确认可用的need/review，保留原方法，通过入口逐级增强 |
| 产品与架构 | 选择三层组合及理由，产品/架构说明 | design/doc |
| MVP与业务Skill | MVP场景选择；I、P、O与异常/验证说明 | scope/build；方法设计不直接实现 |
| 验证、部署、交付 | 测试思路、预期与结果记录方式；部署路线；使用和责任交接 | deliver/run；实际执行和结果另核对 |
| 电梯演讲 | 共同事实底稿、受众重点与简洁演讲稿 | 新增pitch |
| 项目复盘 | SOP/Skill方法规格、决策库条目、日常觉察草稿 | 新增reflect，与开篇知识库闭环 |

知识库先搭容器；SOP和决策依据在项目中产生，再沉淀回来。一句话是便于捕捉，不意味着丢掉适用条件、关键依据或情绪与事实的区别。保存位置和写入授权仍由用户指定，不自动归档或发布。
